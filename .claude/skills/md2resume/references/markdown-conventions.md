# md2resume Markdown 约定（条文）

简历源文件是纯 Markdown。渲染靠 `core/parser.py::parse_markdown` 解析成 `ResumeData`，再由 `core/docx_renderer.py::render_docx` 套用模板设计生成 docx。下面是必须遵守的格式约定。

## 1. 结构骨架

```markdown
# 姓名

- 电话: 138-0000-0000
- 微信: xxx
- 邮箱: xxx@example.com

## 段落标题（教育背景 / 实习经历 / 项目经历 / 核心能力 ...）

### 条目标题 | 副标题 | 日期

- 要点
```

| 元素 | 写法 | 解析行为 |
|---|---|---|
| 姓名 | `# 张三` | 一级标题，仅用于姓名 |
| 联系方式 | `- 电话: ...` / `- 微信: ...` / `- 邮箱: ...` | 第一个 `##` 之前的 `- key: value`，key 自动识别（电话/微信/邮箱/GitHub 等） |
| 段落 | `## 教育背景` | 二级标题 |
| 条目 | `### 公司 | 部门·职位 | 2025.01–2025.05` | 三级标题，**用 `|` 分字段**；含 4 位数字的段自动判为日期，靠右显示 |
| 要点 | `- 内容` | 普通列表项（`-` 或 `*` 均可） |

**条目标题用 `|` 分隔**：`title | subtitle | date`。日期是"含 4 位数字"的那一段，会被右对齐；其余中段拼成副标题（灰色）。例：
- `### 示例大学 | 人工智能 · 本科 | 2022.09–2026.06`
- `### 星河智能 | AI 产品实习生 | 2025.07–2025.12`

## 2. 加粗纪律（重要）

用 `**词语**` 加粗，但**每条要点最多加粗 1–2 个关键词**，不要把所有数字都加粗——否则面试官抓不住重点。

- ✅ `- **付费率提升 0.8PP**，验证分层运营路径`（只突出最关键结果）
- ❌ `- 付费率提升 **0.8PP**，用户 **10 万+**，成本 **$2.3**`（加粗太多 = 没有重点）

**小标题**（冒号前的标签，如 `**数据洞察**：`）算结构性加粗，**不计入**这 1–2 个关键词额度。

## 3. 成果蓝条（成果高亮）⭐

对每段经历的**核心成果/结果**那一行，用 `- > ` 前缀标记，会渲染成**成果高亮蓝条**：

```markdown
- > 内测 8 周，任务完成时长下降 **35%**
```

渲染效果（对齐 `模版.docx`）：
- 浅蓝底色 `#EBF3FB`（整条背景）
- 左侧蓝色竖条 `#2E75B6`
- 文字深蓝 `#1F4E79`，关键词加粗

**用法**：`- ` 后紧跟 `> ` 即触发。每段经历最多 1 条成果蓝条（放该段最亮的结果）。普通要点不要用，否则失去高亮意义。

## 4. 项目子标题

一段经历下若分多个项目，用整条加粗的 bullet 做子标题：

```markdown
- **【项目一】企业内部知识助手**
- **需求调研**：...
```

`**【项目X】标题**`（整条被 `**` 包裹）会渲染成深蓝加粗的项目小标题，无圆点。

## 5. 模板设计系统（配色）

| 角色 | 色值 | 用途 |
|---|---|---|
| 主蓝 | `#2E75B6` | 段落下划线、经历卡片分隔线、bullet 圆点、成果条左竖条 |
| 深蓝 | `#1F4E79` | 姓名、段落标题、公司名、项目子标题、成果条文字 |
| 灰 | `#595959` | 部门/职位副标题、日期 |
| 深灰 | `#404040` | 正文（非纯黑，更柔和） |
| 浅蓝 | `#EBF3FB` | 成果蓝条底色 |

字体：中文微软雅黑，西文 Arial。

## 6. 一页适配

docx 无法像 PDF 那样自动测算页数（需渲染引擎），靠两个参数手调：

```python
render_docx(data, photo_path, scale=1.0, dense=True)
```

- `dense=True`：收紧行距(1.0)、页边距(0.7/1.1cm)、段间距——为"一页 + 大字号"腾空间。
- `scale`：整体等比缩放字号/标题/照片/段距。`1.0` ≈ 正文 9.5pt；`>1` 更大更满，`<1` 更小更松。

**调一页的方法**：先用 `dense=True, scale=1.0` 渲染，用 Quick Look 渲染第 1 页缩略图，确认最后一段（核心能力）完整显示即为一页；若有空白就把 scale 上调（1.02–1.08），若溢出就下调。

## 7. 渲染脚本模板

```python
from pathlib import Path
from core.parser import parse_markdown
from core.docx_renderer import render_docx

SRC = Path("examples/sample_zh.md")
OUT = Path("output/sample.docx")

data = parse_markdown(SRC.read_text("utf-8"))
OUT.write_bytes(render_docx(data, photo_path=None, scale=0.90, dense=True))
```

用 Quick Look 出图自检：`qlmanage -t -s 1700 -o /tmp/ql <file.docx>`。
